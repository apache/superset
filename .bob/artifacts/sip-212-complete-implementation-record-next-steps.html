1. What the Feature Does (End-to-End Flow)

Replaces raster-screenshot-stitched PDFs with Playwright's native page.pdf() — a real vector PDF with selectable text. The new path is strictly additive; any failure falls back silently to the existing screenshot path.

1. Celery worker → execute.py::_get_pdf()
↓
2. Flag check: DASHBOARD_REPORTS_BROWSER_PRINT_PDF=True AND dashboard report → _get_browser_print_pdf()
↓
3. DashboardPrintScreenshot.__init__ builds URL: base URL + ?standalone=3&print=1
↓
4. Playwright navigates, authenticates, waits for .standalone
↓
5. Frontend sees ?print=1: DashboardBuilder adds body.print-mode + PRINT_MODE_CSS; Row.tsx bypasses IntersectionObserver; Tabs.tsx sets forceRender:true + isComponentVisible=true for all tabs
↓
6. UNHIDE_TAB_PANELS_JS runs: strips style="display:none" from all [role="tabpanel"] elements (CSSMotion applies this as a React inline style when forceRender=true — CSS !important cannot override inline styles)
↓
7. PRINT_ALL_CHART_HOLDERS_READY_JS waits until ALL chart holders (not just viewport-visible) reach terminal state
↓
8. UNHIDE_TAB_PANELS_JS runs again (safety), then page.pdf(A4, print_background=true, margins=10mm)
↓
9. Return bytes → caller. Any exception → return None → fall back to screenshot path

3. Roadblocks & How They Were Resolved

1 — DEV_MODE=true skips npm build in Docker

Docker build skips npm run build when DEV_MODE=true. Frontend bundle is stale until built manually on the Mac host. Fix: cd superset-frontend && npm install && npm run build on the Mac. Output lands in superset/static/assets/ (volume-mounted). No Docker rebuild needed.

2 — IntersectionObserver virtualizes off-screen rows

DashboardVirtualization uses IntersectionObserver in Row.tsx to skip rendering charts outside the viewport. In print mode (full-DOM render) all rows must be in-view. Fix: initialize isInView=isPrintMode and guard observer creation with !isPrintMode.

3 — CSS !important cannot override React inline styles

CSSMotion (line 115 in @rc-component/motion/es/CSSMotion.js) renders inactive tab panels with style={{ display: 'none' }} as a React prop when forceRender=true. This becomes an inline style attribute on the DOM node. Inline styles always beat CSS rules, including !important. The CSS fix was written, tested, and confirmed useless. Fix: UNHIDE_TAB_PANELS_JS — evaluated by Playwright outside React's reconciliation loop — directly removes the inline style. Called before the readiness wait and again before page.pdf().

4 — Readiness check was viewport-scoped

REPORT_CHART_HOLDERS_READY_JS filters by getBoundingClientRect() viewport intersection. Tab 2 charts were either display:none'd or off-screen, so the check returned true after only tab 1 loaded. Fix: PRINT_ALL_CHART_HOLDERS_READY_JS — same logic without the viewport filter.

5 — ALERT_REPORTS_NOTIFICATION_DRY_RUN=True blocked verification

Main dev config has dry-run=True: pipeline runs but nothing is delivered. Override in superset_config_docker.py with ALERT_REPORTS_NOTIFICATION_DRY_RUN = False. Dev-only — must not go into PR.

6 — Suspected useLegacyItems stripped forceRender (false alarm)

Suspected antd/es/tabs/hooks/useLegacyItems.js stripped forceRender from items. Read the source: it does ...item spread, preserving all fields. Root cause was Roadblock 3 (CSSMotion inline style), not this.

4. All Compromises & Path to Final Implementation

These are the known gaps. The current state is a working prototype, not production-ready.

C1 — Multi-URL dashboards silently fall back

Dashboards with top-level tabs produce multiple URLs. _get_browser_print_pdf() returns None if len(urls) != 1. Final fix: iterate all URLs, call get_print_pdf() per URL, merge PDFs with pypdf.PdfWriter.

C2 — JS DOM mutation is fragile

UNHIDE_TAB_PANELS_JS mutates the DOM from outside React. It works because the dashboard is stable at the point it runs, but it is technically fragile. Definitive fix: pass visible={true} to every CSSMotion instance in print mode at the React level — override the tab active key in print mode via context so CSSMotion never enters the forceRender+display:none branch at all.

C3 — No chart-type safety limits

No block-list for chart types that don't render headlessly (DeckGL, WebGL). No page-count cap. Final fix: add BROWSER_PRINT_PDF_CHART_TYPE_BLOCKLIST and BROWSER_PRINT_PDF_MAX_PAGES config keys.

C4 — No unit tests

Zero automated coverage for DashboardPrintScreenshot, get_print_pdf(), _get_pdf() flag routing, _get_browser_print_pdf(), Row.tsx print bypass, Tabs.tsx forceRender, SliceHeader canExplore=false.

C5 — No UPDATING.md or docs entry

UPDATING.md needs an entry for the new flag. docs/ needs a user-facing section on how to enable browser-print PDFs.

C6 — docker dev config changes must not go into PR

docker/pythonpath_dev/superset_config_docker.py has the flag enabled and dry-run disabled. This must be reverted before the PR is opened.

C7 — page.pdf() has no explicit timeout

The page.pdf() call uses the context-level default timeout. For large dashboards the PDF generation itself could be slow. Final fix: derive an explicit timeout from the remaining budget after the readiness wait.

In _get_browser_print_pdf() in execute.py, replace the if len(urls) != 1: return None guard with a loop:

from pypdf import PdfWriter

pdf_pages = PdfWriter()
for url in urls:
    screenshot = DashboardPrintScreenshot(url, ...)
    pdf_bytes = screenshot.get_print_pdf(user=user, ...)
    if not pdf_bytes:
        return None  # any tab failing falls back to screenshot path
    reader = pypdf.PdfReader(io.BytesIO(pdf_bytes))
    for page in reader.pages:
        pdf_pages.add_page(page)

output = io.BytesIO()
pdf_pages.write(output)
return output.getvalue()
