# Product acceptance bugs: retest against the current build

2026-11-03, build `159def3613` on `asset-demo`, tested by hand against a
running instance as the real accounts (alex and priya, both editors; admin
where a page required it).

Elizabeth filed eleven bugs on 2026-10-23 against build `d4959daf` and
recommended not shipping, on acceptance criterion 2: nothing reaches
viewers without a second editor's approval, through the UI and the API.
This retests all eleven.

**Eight pass. Two are partly fixed. One is pending a scope decision.**

Acceptance criterion 2 itself now holds on every route tested here.

## A note on the tracker before the detail

Every one of these eleven is still sitting in **Backlog**, except 129075
which is **Blocked**. Nothing has been moved as fixes landed, so the ticket
states carry no information about the build. Eight of them can be closed on
this evidence.

## The eight that pass

**129068, legacy endpoints.** `POST /superset/explore/?action=overwrite`
answers 202 and captures a change request; the chart name does not move.
`POST /datasource/save/` answers 422 with a message naming the reviewed
route to use instead; the dataset name does not move. The ticket's third
step, a 500 that still commits, cannot arise now because the route is
refused before anything is written.

**129069, adding a chart to a published dashboard.** Dashboard 7 is
published. Adding a chart to its layout answers 202, the live
`position_json` is unchanged, and the reviewer's panel reads
`layout: added 1`.

**129070, approving a version never reviewed.** Submitted, then withdrawn,
rewritten and resubmitted so the content moved under the reviewer.
Approving while quoting the old version is refused with 409 and the live
title does not move. Approving while quoting *no* version is also refused:
the check used to be skipped when the field was absent, which made it
bypassable by any caller.

**129071, undo and double-apply.** Two approvals fired together answer 200
and 409, so it applies once. For the undo half: a rename was held for
review on a dataset, an exempt field (the description) was changed while it
sat there, and approving applied the rename without reverting the
description. Approvals replay the author's field-level command rather than
a whole snapshot, which is what makes that safe.

**129073, apply immediately.** Dataset description, editors list and Sync
columns from source each answer 200 and apply directly, with no request
raised.

**129074, banner and Request review after a save.** Edited the dashboard
title through Edit properties and saved. In the same document, with no
reload: the banner reads "Your changes are saved ... you and viewers are
both seeing the live version", the toast reads "Changes saved. Viewers
still see the live version. Review changes", and both Request review and
What changed are offered. The header still shows the live title, which is
correct and is what the banner says.

**129076, empty change.** Saving a dashboard with its existing title
answers 200 and creates no change request.

**129077, Published toggle.** Unpublishing answers 202 and is held;
`published` stays true until approval; the reviewer sees a plain
`true -> false`. The copy reads "Changes saved. Viewers still see the live
version", which no longer contradicts what happens. Tested through the API;
the toggle's own toast was not separately driven.

## The two that are partly fixed

**129075, reviewers cannot see what changed.** Three of the four complaints
are addressed. A dataset review shows a real definition diff. A chart's
settings are now named the way Explore names them ("Auto Zoom", "Fixed
Color") instead of raw keys, and a value longer than 300 characters is no
longer rendered as if the field had been emptied, which had made a
rewritten SQL body invisible.

What remains:

- There is still no preview for a chart. `canPreview` requires a dashboard,
  so a chart reviewer sees the live chart and a list of setting names, with
  no way to see the proposed chart.
- The panel names at most three settings and collapses the rest to "and N
  more", with no way to expand.
- Some real controls still show raw names, for example `matrixify_enable`
  and `annotation_layers`.
- No before and after values for anything inside `params`.
- **New defect found during this retest.** On a dashboard saved from edit
  mode, the panel listed `map_label_colors` and `shared_label_colors` as
  what changed. Both are in `DERIVED_METADATA_KEYS`, the set the gate
  deliberately ignores because Superset recomputes them. The gate excludes
  them at `changes.py:281`; the panel's key list comes from
  `changed_keys_by_kind` at `api.py:324`, which does not. So the reviewer
  is shown two keys the author never touched, and is not shown whatever
  actually caused the field to be flagged.

**129078, deleting an asset with a pending change.** The replacement still
happens: a pending `update` on a chart became a `draft` `delete` on the
same request, with its fields emptied and `submitted_at` cleared, so the
approver's queued item disappears. One open change per asset is the design,
so a replacement is expected; what the ticket objects to is that it was
silent. In this direction it no longer is. The response reads "Delete saved
as a draft. Nothing has been removed, and it replaced the edit you had
waiting."

The reverse direction is still silent, and it is the worse one. A delete
that has already been **submitted for review** is replaced by any ordinary
save from its author: the request returns to draft, its operation changes
from delete to update, and the author is told only "Changes updated in your
existing draft". Nothing says a submitted delete was discarded, and the
approver's queue item vanishes with no notice. This was found independently
during an adversarial pass and is the same code path as 129078.

## The one pending a decision

**129072, imports.** An import that updates an existing dashboard, chart or
dataset is still refused, with a message directing the author to make the
change in Superset instead. SOW 5.1 and Visa Q12 put imports in V1, so this
is a deliberate narrowing of scope rather than a defect: capturing an
import means storing an uploaded archive and replaying it on approval, and
the change-request table is not somewhere to put a zip. Refusing is the
honest behaviour until that exists, but it is a departure that needs Visa's
agreement, and it is the one item here that cannot be closed by testing.
