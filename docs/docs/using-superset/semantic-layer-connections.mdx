## Provider-defined connection forms

Installed semantic-layer extensions supply their connection fields and help text.
Required fields are marked with an asterisk. Examples in empty fields are placeholders,
not selected values. Follow the provider's field help for optional and conditionally
required settings.

A nullable password is displayed as one optional password input. Leaving an untouched
null value blank preserves it; clearing a value sends an empty string. Providers decide
how these values are interpreted.

Providers can mark a private-key field with `x-input-type: pem` to request a multiline
editor. Paste the whole key, including matching BEGIN and END lines. The inline check
only checks the private-key envelope, not cryptographic validity. Password-protected
keys also need their passphrase. The hint is for private keys, not certificates.

Automatic metadata discovery is debounced. Discovery failures do not prevent entering
manual values when suggestions are unavailable. Errors use fixed messages rather than
displaying provider exceptions. Saved secrets remain masked while editing; retaining
a mask preserves the saved secret on Save. Changing connection dependencies can clear
dependent selections, so check those fields before saving.
