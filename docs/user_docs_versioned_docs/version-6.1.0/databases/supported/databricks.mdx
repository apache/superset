### Upgrading legacy connections

Workspaces upgrading from 6.0 with a legacy Databricks connection have their
`databricks+connector://` URI automatically migrated to `databricks://` during
`superset db upgrade`. The migration preserves credentials, HTTP path, catalog,
and the rest of the URI. No API access or manual connection recreation is needed.

Edit the connection to review the saved host, HTTP path, catalog, schema, and
masked access token, or enter a replacement token. When creating a connection
with a SQLAlchemy URI, **Connect this database using the dynamic form instead**
opens the field-based form.

Downgrading restores the old scheme on locally converted connections only when
their URI, settings, and modification timestamp still match the migrated state.
Imported connections carrying the conversion marker are also eligible for rollback. Connections created natively with `databricks://` are not reverted. Malformed
`extra` settings do not block the upgrade: their text is preserved, and only the URI
scheme changes. The migration keeps fingerprints in a bookkeeping table so these
connections can also be safely downgraded without parsing their settings. Invalid
settings may still need correction before the connection can execute queries.
