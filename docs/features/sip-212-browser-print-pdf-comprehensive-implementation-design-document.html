1. Verified Investigation Findings

1.1 — Report Execution Flow (Backend)

The current PDF path is in superset/commands/report/execute.py. The call chain for a PDF dashboard report:

BaseReportState._get_notification_content() [line 1232] → checks report_schedule.report_format == ReportDataFormat.PDF → calls _get_pdf() [line 862] → calls _get_screenshots() → list[bytes] [line 745] → builds DashboardScreenshot objects for each URL → calls screenshot.get_screenshot(user, ...) → BaseScreenshot.get_screenshot() [screenshots.py:240] → chooses WebDriverPlaywright or WebDriverSelenium → calls driver.get_screenshot(url, element, user, ...) → WebDriverPlaywright.get_screenshot() [webdriver.py:564] → new browser context + page → page.goto(url) → wait for .standalone element → wait for .chart-container elements → _wait_for_charts_ready() [webdriver.py:302] → page.screenshot(full_page=True) [webdriver.py:297] → build_pdf_from_screenshots(screenshots) [pdf.py:30] → PIL Image.open each PNG → images[0].save(new_pdf, "PDF", save_all=True) → NotificationContent with pdf= field set → _send() dispatches to email/Slack/webhook
Key verified fact: Today's "PDF" is literally a sequence of PNG raster screenshots stitched by PIL into a PDF container — not a native-print PDF. The page.pdf() Playwright API is available but never called.

Key readiness predicate (REPORT_CHART_HOLDERS_READY_JS) — verified

The JS predicate polled by page.wait_for_function() scans .dashboard-component-chart-holder[class*="dashboard-chart-id-"] elements that are in the current viewport (using getBoundingClientRect()) and returns true only when: at least one holder exists, all viewport-visible holders show a terminal marker (.slice_container, [role="alert"], .ant-empty, or .missing-chart-container), and none show a .loading spinner.

Critical limitation for SIP-212: The readiness predicate is scoped to viewport-visible holders only (the r.top < window.innerHeight && r.bottom > 0 check). Elements below the fold are classified as 'virtualized' and are skipped. This means the existing readiness mechanism is designed for a fixed-viewport screenshot — it explicitly does not guarantee off-screen charts have rendered. For browser print (which renders the full DOM), we must force all charts to render before printing.

4. Decision Points and Chosen Approaches

4.1 — Readiness Signal Strategy: DOM-based vs. Redux-based

The prompt suggests a data-* DOM attribute as the readiness signal. The backend already polls DOM state via JS predicates. The existing REPORT_CHART_HOLDERS_READY_JS is close to what we need but is viewport-scoped.

Decision: Add a new JS predicate PRINT_CHART_HOLDERS_READY_JS to screenshot_utils.py that is identical to REPORT_CHART_HOLDERS_READY_JS but removes the getBoundingClientRect() viewport filter — all chart holders must be terminal, not just viewport-visible ones. This is:

  • The least invasive change (one extra constant in an existing file)
  • Consistent with the existing polling pattern (page.wait_for_function())
  • No frontend code change required for the basic readiness signal

A data-report-ready DOM attribute approach is an alternative but requires a new React side-effect that writes to the DOM from Redux state — more moving parts than extending the existing JS polling approach.

4.2 — Print-Ready URL Mode: Extend REPORT vs. Add New Value

The existing standalone=3 (REPORT) mode already does what we need: strips header, filter bar, edit controls, disables auto-refresh. The main gap is CSS (layout and table expansion), not the URL mode itself.

Decision: Reuse standalone=3 (REPORT) for the print path rather than adding standalone=4. The print-specific CSS will be gated on a separate URL parameter ?print=1 (added by the new DashboardPrintScreenshot class). This avoids any risk of breaking existing embedded SDK consumers who use standalone=3, and keeps the standalone enum unchanged.

4.3 — Where to Insert the Decision Point

Decision: Override _get_pdf() in execute.py to check the feature flag and route to either a new _get_browser_print_pdf() method or the existing screenshot-based flow. The existing _get_screenshots() is completely untouched.

4.4 — Table Expansion (Phase D / Stretch)

For the demo scope, the table overflow expansion is handled via CSS (@media print + .table-viz { overflow: visible; max-height: none; }) rather than the Phase D server-side data fetch path. This is sufficient to demonstrate the improvement over screenshot clipping for moderate-sized tables and defers the complex data-fetch approach to future work.

5.3 — Force-Render All Charts (Disable Virtualization in Print Mode)

The DASHBOARD_VIRTUALIZATION feature flag and the isInView prop on chart holders cause off-screen charts to not render. In print mode, all charts must render immediately.

In DashboardBuilder.tsx, add a check: if isPrintMode (derived from the ?print=1 URL param), pass isInView={true} to all chart components (or pass a printMode prop down that overrides virtualization). The relevant prop is isComponentVisible on the chart grid component.

Additionally, add the body class in DashboardBuilder.tsx:

const isPrintMode = getUrlParam(URL_PARAMS.print) === 1;

useEffect(() => {
  if (isPrintMode) {
    document.body.classList.add('print-mode');
    return () => document.body.classList.remove('print-mode');
  }
  return undefined;
}, [isPrintMode]);

6. Phase B — Readiness Signal (Frontend → Backend Bridge)

6.1 — New JS Readiness Predicate: All Charts (Not Just Viewport)

Add to superset/utils/screenshot_utils.py:

# Like REPORT_CHART_HOLDERS_READY_JS, but checks ALL chart holders,
# not just viewport-visible ones — required for browser-print mode where
# the full DOM is printed, not just the visible viewport.
PRINT_CHART_HOLDERS_READY_JS_BODY = f"""
    const holders = document.querySelectorAll('{CHART_HOLDER_SELECTOR}');
    const unready = [];
    for (const holder of holders) {{
        const hasSliceContainer = holder.querySelector(
            '{SLICE_CONTAINER_SELECTOR}'
        ) !== null;
        const stillLoading = holder.querySelector('{LOADING_SELECTOR}') !== null;
        const isReady = holder.querySelector('{TERMINAL_MARKER_SELECTOR}') !== null;
        if (stillLoading || !isReady) {{
            const chartIdMatch = holder.className.match(/{CHART_ID_CLASS_PATTERN}/);
            const chartId = chartIdMatch ? chartIdMatch[1] : null;
            unready.push({{ chartId: chartId }});
        }}
    }}
"""

PRINT_CHART_HOLDERS_READY_JS = (
    f"() => {{ {PRINT_CHART_HOLDERS_READY_JS_BODY} "
    "return holders.length > 0 && unready.length === 0; }"
)

This predicate is identical to the existing REPORT_CHART_HOLDERS_READY_JS except the getBoundingClientRect() viewport intersection check is removed — every chart holder in the DOM must be terminal, regardless of scroll position.

7.2 — New DashboardPrintScreenshot class

Add to superset/utils/screenshots.py a subclass that sets the print URL:

class DashboardPrintScreenshot(DashboardScreenshot):
    """
    A DashboardScreenshot subclass for the browser-print PDF path.
    Sets standalone=3 (REPORT) and print=1 on the URL, and uses
    Playwright's page.pdf() instead of page.screenshot().
    """

    def __init__(
        self,
        url: str,
        digest: str | None,
        window_size: WindowSize | None = None,
        thumb_size: WindowSize | None = None,
    ):
        super().__init__(url, digest, window_size, thumb_size)
        # Add print=1 to signal the frontend to apply print-mode CSS
        # and force-render all charts regardless of viewport position.
        self.url = modify_url_query(self.url, print=1)

    def get_print_pdf(
        self,
        user: User,
        window_size: WindowSize | None = None,
        log_context: str | None = None,
        report_execution_context: ReportExecutionContext | None = None,
    ) -> bytes | None:
        """
        Use Playwright's page.pdf() to generate a native print PDF.
        Returns None if Playwright is not available or not preferred.
        """
        if not feature_flag_manager.is_feature_enabled(
            "PLAYWRIGHT_REPORTS_AND_THUMBNAILS"
        ):
            return None
        if not PLAYWRIGHT_AVAILABLE:
            return None
        driver = WebDriverPlaywright(self.driver_type, window_size or self.window_size)
        return driver.get_print_pdf(
            self.url,
            user,
            log_context=log_context,
            report_execution_context=report_execution_context,
        )

7.3 — New get_print_pdf() method on WebDriverPlaywright

Add to superset/utils/webdriver.py inside WebDriverPlaywright:

def get_print_pdf(
    self,
    url: str,
    user: User | None = None,
    log_context: str | None = None,
    report_execution_context: ReportExecutionContext | None = None,
) -> bytes | None:
    """
    Render the dashboard in print-ready mode and call page.pdf().

    Uses PRINT_CHART_HOLDERS_READY_JS (all chart holders, not just
    viewport-visible ones) to detect readiness, then calls
    Playwright's native page.pdf() instead of page.screenshot().
    """
    if not PLAYWRIGHT_AVAILABLE:
        return None

    browser_args = app.config["WEBDRIVER_OPTION_ARGS"]
    browser = _browser_manager.get_browser(browser_args)
    # Use a wide viewport for print rendering
    context = browser.new_context(
        bypass_csp=True,
        viewport={"height": self._window[1], "width": self._window[0]},
        device_scale_factor=app.config["WEBDRIVER_WINDOW"].get("pixel_density", 1),
    )
    context.set_default_timeout(app.config["SCREENSHOT_PLAYWRIGHT_DEFAULT_TIMEOUT"])
    if user:
        self.auth(user, context)
    page = context.new_page()
    pdf_bytes: bytes | None = None
    try:
        # Navigate to print-ready URL
        page.goto(
            url,
            wait_until=app.config["SCREENSHOT_PLAYWRIGHT_WAIT_EVENT"],
        )
        page.wait_for_timeout(app.config["SCREENSHOT_SELENIUM_HEADSTART"] * 1000)

        # Wait for the standalone element to confirm dashboard has mounted
        page.locator(".standalone").wait_for()

        # Wait for ALL chart holders to reach a terminal state
        # (not just viewport-visible ones — print renders the full DOM)
        load_wait = app.config["SCREENSHOT_LOAD_WAIT"]
        effective_wait = (
            report_execution_context.deadline.timeout_seconds("chart_readiness")
            if report_execution_context
            else float(load_wait)
        )
        page.wait_for_function(
            PRINT_CHART_HOLDERS_READY_JS,
            timeout=effective_wait * 1000,
        )

        # Capture via native browser print engine
        pdf_bytes = page.pdf(
            format="A4",
            print_background=True,
            margin={
                "top": "10mm",
                "bottom": "10mm",
                "left": "10mm",
                "right": "10mm",
            },
        )
        logger.info(
            "Browser-print PDF generated: %d bytes for url: %s",
            len(pdf_bytes) if pdf_bytes else 0,
            url,
        )
    except (PlaywrightTimeout, PlaywrightError, Exception):
        logger.exception(
            "Browser-print PDF failed for url %s; caller should fall back "
            "to screenshot path",
            url,
        )
        return None
    finally:
        context.close()
    return pdf_bytes

7.4 — Decision Point in execute.py

Modify superset/commands/report/execute.py in the _get_pdf() method. The existing screenshot-based path must remain completely intact as the fallback:

def _get_pdf(self) -> bytes:
    """
    Get chart or dashboard pdf.
    If DASHBOARD_REPORTS_BROWSER_PRINT_PDF is enabled, attempt
    the browser-native print path first; fall back to screenshots
    on any failure or if the flag is off.
    :raises: ReportSchedulePdfFailedError
    """
    # NEW: Attempt browser-print path if feature flag is on
    if (
        feature_flag_manager.is_feature_enabled(
            "DASHBOARD_REPORTS_BROWSER_PRINT_PDF"
        )
        and self._report_schedule.dashboard  # Dashboard reports only
    ):
        try:
            pdf_bytes = self._get_browser_print_pdf()
            if pdf_bytes:
                logger.info(
                    "Browser-print PDF success for %s",
                    self._log_context,
                )
                return pdf_bytes
            logger.warning(
                "Browser-print PDF returned None for %s; "
                "falling back to screenshot path",
                self._log_context,
            )
        except Exception:  # noqa: BLE001
            logger.exception(
                "Browser-print PDF failed for %s; "
                "falling back to screenshot path",
                self._log_context,
            )

    # EXISTING PATH — completely unchanged
    screenshots = self._get_screenshots()
    reserve_seconds = (
        self._report_execution_context.post_capture_reserve_seconds
        if self._report_execution_context
        else 0.0
    )
    self._phase_timeout("pdf_generation", reserve_seconds=reserve_seconds)
    pdf = build_pdf_from_screenshots(screenshots)
    self._phase_timeout("pdf_generation", reserve_seconds=reserve_seconds)
    return pdf

def _get_browser_print_pdf(self) -> bytes | None:
    """
    Attempt native browser-print PDF generation for a dashboard report.
    Returns None (does not raise) on any failure so the caller can
    fall back to the screenshot path.
    """
    urls = self.get_dashboard_urls()
    user, _ = resolve_executor_user(self._report_schedule)
    window_width, window_height = app.config["WEBDRIVER_WINDOW"]["dashboard"]
    max_width = app.config["ALERT_REPORTS_MAX_CUSTOM_SCREENSHOT_WIDTH"]
    width = min(max_width, self._report_schedule.custom_width or window_width)
    height = self._report_schedule.custom_height or window_height
    window_size = (width, height)

    # Only single-URL dashboards for the demo (multi-tab support deferred)
    if len(urls) != 1:
        logger.info(
            "Browser-print PDF: multi-tab dashboard not yet supported "
            "(%d URLs); falling back to screenshot path",
            len(urls),
        )
        return None

    screenshot = DashboardPrintScreenshot(
        urls[0],
        self._report_schedule.dashboard.digest,
        window_size=window_size,
        thumb_size=app.config["WEBDRIVER_WINDOW"]["dashboard"],
    )
    return screenshot.get_print_pdf(
        user=user,
        log_context=self._log_context,
        report_execution_context=self._report_execution_context,
    )
Invariant preserved: The existing _get_screenshots() method is not modified at all. The existing path runs identically when the flag is off. When the flag is on and the new path fails (any exception, timeout, or None return), the existing path still executes.

8. Fallback and Safety Design

REPORT TRIGGERED ↓ _get_notification_content() → report_format == PDF ↓ _get_pdf() ↓ Is DASHBOARD_REPORTS_BROWSER_PRINT_PDF enabled? ├─ NO ──────────────────────────────────────────────────────→ [EXISTING PATH] │ _get_screenshots() └─ YES build_pdf_from_screenshots() ↓ Is this a dashboard report (not chart)? ├─ NO ─────────────────────────────────────────────────→ [EXISTING PATH] └─ YES ↓ Is it a single-URL dashboard (not multi-tab)? ├─ NO (multi-tab) ──────────────────────────────→ [EXISTING PATH] └─ YES ↓ _get_browser_print_pdf() DashboardPrintScreenshot.get_print_pdf() ↓ Is PLAYWRIGHT available? ├─ NO ──────────────────────────────────────→ [EXISTING PATH] └─ YES ↓ page.goto() + .standalone wait ↓ PRINT_CHART_HOLDERS_READY_JS within timeout? ├─ TIMEOUT ─────────────────────────→ [EXISTING PATH] └─ READY ↓ page.pdf() succeeds? ├─ EXCEPTION/None ─────────────→ [EXISTING PATH] └─ bytes ↓ return pdf_bytes ✓

Timeout Behavior

The new path uses the same SCREENSHOT_LOAD_WAIT config (default: 60s) as the existing readiness wait. If Playwright's page.wait_for_function() raises PlaywrightTimeout, it is caught by the except Exception in get_print_pdf(), which returns None, triggering fallback to the screenshot path.

For page.pdf() itself, the existing SCREENSHOT_PLAYWRIGHT_DEFAULT_TIMEOUT (60,000 ms) covers the call via the context default timeout.

12. Open Questions

  1. DashboardVirtualization override mechanism: The exact prop chain from DashboardBuilder to individual chart holders that controls lazy-rendering needs to be traced to determine the minimal change. The isComponentVisible prop on the DashboardGrid component is the likely injection point, but verification in DashboardContainer.tsx and the chart holder component is needed before implementation.
  2. page.pdf() format options: Should the PDF format (A4 vs Letter) be configurable via a new config key, or hard-coded for the demo? The A4 default matches the SIP proposal.
  3. Multi-tab dashboard handling: The demo defers this. When implemented, each tab would require a separate page.pdf() call and the results would need merging — likely requiring a PDF merge library (pypdf or pdfmerge). This is the Phase 5 optional item from the SIP.
  4. Budget/deadline accounting for new path: ReportExecutionContext tracks phases against a Celery task deadline. The new get_print_pdf() call should either receive the context and respect its deadline, or the budget phases need to be added. For the demo, using the existing SCREENSHOT_LOAD_WAIT timeout is acceptable.
  5. Selenium fallback for print path: Should the print path attempt Selenium if Playwright is unavailable? Selenium does not have a page.pdf() equivalent — so the answer is no; Playwright is a hard requirement for the print path.
