1. What the Feature Does (End-to-End Flow)

Replaces raster-screenshot-stitched PDFs with Playwright's native page.pdf() — a real vector PDF with selectable text. The new path is strictly additive; any failure falls back silently to the existing screenshot path.

1. Celery worker → execute.py::_get_pdf()
↓
2. Flag check: DASHBOARD_REPORTS_BROWSER_PRINT_PDF=True AND dashboard report AND single-URL → _get_browser_print_pdf()
↓
3. DashboardPrintScreenshot.__init__ builds URL: base URL + ?standalone=3&print=1
↓
4. Playwright navigates (viewport=1600px wide), authenticates, waits for .standalone
↓
5. Frontend sees ?print=1: DashboardBuilder adds body.print-mode + PRINT_MODE_CSS; Row.tsx bypasses IntersectionObserver; Tabs.tsx sets forceRender:true + isComponentVisible=true for all tabs; SliceHeader disables chart-title links
↓
6. UNHIDE_TAB_PANELS_JS runs: strips style="display:none" from all [role="tabpanel"] elements (CSSMotion applies this as a React inline style when forceRender=true — CSS !important cannot override inline styles)
↓
7. PRINT_ALL_CHART_HOLDERS_READY_JS waits until ALL chart holders (not just viewport-visible) reach terminal state
↓
8. UNHIDE_TAB_PANELS_JS runs again (safety net for React reconciliation), then EXPAND_TABLE_CONTAINERS_JS removes inline height/overflow from table scroll containers
↓
9. page.pdf(format="A4", print_background=True, scale=794/1600, margin=10mm) — scale ratio maps 1600px-wide layout to A4 paper width without blank guttering
↓
10. Return bytes → caller. Any exception → return None → fall back to screenshot path

3. All Technical Discoveries

D1 — DEV_MODE=true skips npm build in Docker

Docker build skips npm run build when DEV_MODE=true (set in docker-compose.yml). The frontend bundle is stale until built manually on the Mac host. Run: cd superset-frontend && npm install && npm run build. Output lands in superset/static/assets/ (volume-mounted). No Docker rebuild needed.

D2 — IntersectionObserver virtualizes off-screen rows

DashboardVirtualization uses IntersectionObserver in Row.tsx to skip rendering charts outside the viewport. In print mode (full-DOM render) all rows must be in-view. Fix: initialize isInView=isPrintMode and guard observer creation with !isPrintMode.

D3 — CSS !important cannot override React inline styles (the CSSMotion trap)

CSSMotion (node_modules/@rc-component/motion/es/CSSMotion.js line 115) renders inactive tab panels with style={{ display: 'none' }} as a React prop when forceRender=true. This becomes an inline style attribute on the DOM node. Inline styles always beat CSS rules including !important. The CSS fix was written, tested, confirmed useless. Fix: UNHIDE_TAB_PANELS_JS — evaluated by Playwright outside React's reconciliation loop — directly removes the inline style. Called before and after the readiness wait.

D4 — Readiness check was viewport-scoped

REPORT_CHART_HOLDERS_READY_JS filters by getBoundingClientRect() viewport intersection. Tab 2 charts were either display:none'd or off-screen, so the check returned true after only tab 1 loaded. Fix: PRINT_ALL_CHART_HOLDERS_READY_JS — same logic without the viewport filter.

D5 — Viewport/paper mismatch and the scale solution

Setting viewport to 794px (A4 width) makes ECharts/canvas draw tiny because they measure container size at mount. Setting viewport to 1600px (authored dashboard width) and using page.pdf(scale=794/1600=0.496) gives the PDF engine the same rendering as the browser's print-to-PDF with a custom scale, fitting A4 exactly. Formula: _pdf_scale = min(1.0, 794 / pdf_viewport_width). The 794 is A4 width in CSS px at 96 dpi. This is configurable via BROWSER_PRINT_PDF_VIEWPORT_WIDTH.

D6 — Table scroll container clips rows in page.pdf()

The table viz renders all 1000 rows into the DOM but wraps them in a <div style="height: 828px; overflow: auto">. page.pdf() respects this inline height — only ~30 rows visible at 828px. Fix: EXPAND_TABLE_CONTAINERS_JS walks every .superset-chart-table, finds child divs with both an inline height and overflow:auto/scroll, removes height and sets overflow:visible. Then walks up ancestors to remove their inline heights too. CSS rules (printMode.ts) handle class-rule overflow:hidden that JS cannot detect (since those are CSS classes, not inline styles — .dashboard-chart has overflow: hidden in its stylesheet). The :has() selector in printMode.ts handles the ancestor chain for table charts specifically.

D7 — Worker logs at WARNING by default

The Celery worker's root logger is at WARNING when it starts, which blocks INFO logs from our code. INFO logs do appear once Flask app context is entered, but only if the Flask app's logging config sets INFO. When running scripts directly with python3, INFO appears fine. This affects whether browser_print_pdf_unhide and browser_print_pdf_expand_tables logs appear in docker logs output.

D8 — docker dev config is gitignored (no revert needed)

docker/pythonpath_dev/superset_config_docker.py is listed in docker/pythonpath_dev/.gitignore with a catch-all * pattern. It will never appear in git status as tracked or untracked. No action needed before PR.

D9 — pre-commit is not available on the Mac host PATH

pre-commit is installed inside the Docker container at /app/.venv/bin/pre-commit. The Mac host has Python 3.9 but the project's pyproject.toml uses SQLAlchemy 2.x which doesn't have RemovedIn20Warning — system pytest fails. To run pre-commit, either use the Docker container or activate a proper Python 3.11 venv with Superset's dependencies.

D10 — AsyncExecuteReportScheduleCommand cannot be run outside Celery

The command calls get_executor() which raises ExecutorNotFoundError when there is no Celery request context (no task_id bound to a worker). Direct testing must go through the lower-level DashboardPrintScreenshot.get_print_pdf() or the webdriver's get_print_pdf() directly.

D11 — Report schedule recipients association table

The report_schedule table does NOT have an owners column directly — owners are in a junction table. When creating a report schedule via raw SQL, omit the owners field. The schedule still works without explicit owners for testing purposes.

D12 — panels_unhidden=0 is expected for dashboards without tabs

For a dashboard with no tab components (like dashboard 10), UNHIDE_TAB_PANELS_JS finds no tabpanel elements and returns 0 — this is correct and expected. Only dashboards with rc-tabs will show panels_unhidden > 0.

4. All Compromises & Path to Final Implementation

The feature is working for single-URL dashboards. The gaps below are known and must be addressed before the PR can merge.

C1 — Multi-URL dashboards silently fall back deferred

Dashboards with top-level tabs produce multiple URLs. _get_browser_print_pdf() returns None if len(urls) != 1, falling back to the screenshot path. Phase 5 fix: iterate all URLs, call get_print_pdf() per URL, merge PDFs with pypdf.PdfWriter.

C2 — JS DOM mutation is fragile works but not ideal

UNHIDE_TAB_PANELS_JS mutates the DOM from outside React. It works because the dashboard is stable at the point it runs. Definitive fix: pass a React context signal to CSSMotion so it never enters the forceRender+display:none branch at all in print mode.

C3 — No chart-type safety limits not started

No block-list for chart types that may not render headlessly (DeckGL WebGL). No page-count cap. Final fix: add BROWSER_PRINT_PDF_CHART_TYPE_BLOCKLIST and BROWSER_PRINT_PDF_MAX_PAGES config keys.

C4 — Python unit tests need a venv to run tests written, runner missing

Tests are written and syntactically correct but cannot be run on the Mac host (no Superset venv). They can be run inside the Docker container. The test file is at tests/unit_tests/utils/test_browser_print_pdf.py.

C5 — pre-commit must be run before PR pending

per AGENTS.md this is mandatory. Must be run inside Docker container or a proper Superset Python venv. See Section 5 for the exact command.

C6 — page.pdf() has no explicit deadline-aware timeout uses context default

The page.pdf() call uses the Playwright context-level default timeout. For very large dashboards the PDF engine step itself could overrun. Fix: derive an explicit timeout from the remaining deadline budget after the readiness wait.

C7 — Pie chart label truncation on small layout cosmetic

With only 6 columns at 1600px, the pie chart may truncate outer labels at the right edge. Not a functional issue — data is selectable in PDF. Can be improved with a larger chart height in the layout or by tuning outerRadius.

4 Phase 5 — Multi-URL PDF merge (after PR merges)

In _get_browser_print_pdf() in execute.py, replace the single-URL guard with a loop that merges per-URL PDFs:

from pypdf import PdfWriter
import io

pdf_writer = PdfWriter()
for url in urls:
    shot = DashboardPrintScreenshot(url, dashboard.digest, window_size=window_size)
    page_bytes = shot.get_print_pdf(user=user, log_context=self._log_context)
    if not page_bytes:
        return None  # any tab failing falls back to screenshot path
    import pypdf
    reader = pypdf.PdfReader(io.BytesIO(page_bytes))
    for page in reader.pages:
        pdf_writer.add_page(page)

output = io.BytesIO()
pdf_writer.write(output)
return output.getvalue()

Add pypdf to requirements/base.txt. Write a unit test for the merge path (mock get_print_pdf to return fake PDF bytes, assert writer.add_page called correct number of times).
