1. What the Feature Does (End-to-End Flow)

Replaces raster-screenshot-stitched PDFs with Playwright's native page.pdf() — a real vector PDF with selectable text. The new path is strictly additive; any failure falls back silently to the existing screenshot path. Gated by feature flag DASHBOARD_REPORTS_BROWSER_PRINT_PDF (default: False).

1. Celery worker → execute.py::_get_pdf()
↓
2. Flag check: DASHBOARD_REPORTS_BROWSER_PRINT_PDF=True AND dashboard report AND single-URL → _get_browser_print_pdf()
↓
3. DashboardPrintScreenshot.__init__ builds URL: base URL + ?standalone=3&print=1 (+ &print_font_size=medium|large if non-small) (+ &print_layout=2col if 2col) (+ &print_orientation=landscape|auto if non-portrait)
↓
4. Playwright navigates (viewport=1600px wide), authenticates via machine_auth_provider_factory. page.goto() uses explicit timeout=effective_wait*1000. Waits 3s headstart. locator(".standalone").wait_for(timeout=effective_wait*1000).
↓
5. Frontend sees ?print=1: DashboardBuilder adds body.print-mode + injects PRINT_MODE_CSS + getPrintFontSizeCSS(tier) + getPrintLayoutCSS(layout) + getPrintOrientationCSS(orientation) as a single style tag. Default tier when ?print_font_size absent: small (returns empty string — no overrides). Row.tsx bypasses IntersectionObserver. Tabs.tsx sets forceRender:true. SliceHeader disables chart-title links.
↓
6. UNHIDE_TAB_PANELS_JS: strips inline style="display:none" from all [role="tabpanel"] elements.
↓
7. PRINT_ALL_CHART_HOLDERS_READY_JS waits until ALL chart holders reach terminal state. Uses timeout=effective_wait*1000.
↓
8. SHOW_ALL_TABLE_ROWS_JS: fires onChange(0) on the antd Select fiber of each paginated table to expand all rows. Waits 600ms for React re-render. Server-paginated tables are logged as warnings.
↓
9. EXPAND_TABLE_CONTAINERS_JS: (a) removes inline height/overflow/width from table scroll containers; (b) walks up the ancestor chain to .grid-content, releasing height:auto at every level and converting flex→block on each flex ancestor; (c) releases sibling column wrapper heights in the same .grid-row; (d) releases .dragdroppable-row wrapper and converts to block.
↓
10. MEASURE_TABLE_COLUMNS_JS: measures rendered column widths from table[0]'s thead (useSticky header-sizer). Returns array of {tableIndex, totalWidth, colWidths[]}.
↓
11. BAND_TABLE_COLUMNS_JS: for tables with columns too wide to fit one page — applies Situation B fixes (text-wrap → header rotation → truncation → pull-out), then greedy-packs columns into page-width bands (≥2 bands fires; 1 band deferred to SCALE_WIDE_TABLES_JS). Each band is a complete standalone <table> with <thead> + <tbody> from the dual-table useSticky structure.
↓
12. SCALE_WIDE_TABLES_JS: for tables that are still wider than usable width (1-band case or post-banding). Applies CSS transform:scale() to the scroll-container (not the inner <table>). Sets position:relative on sticky thead/th to prevent collapse under transform. 10% tolerance: only fires when table width exceeds maxWidth * 1.10. In auto orientation mode, marks wide-table roots with data-print-landscape="true".
↓
13. SET_PRINT_FONT_SIZE_JS patches inline font-size on .header-line elements: medium=64px, large=96px. (CSS !important cannot override inline React styles.)
↓
14. If print_layout="2col": ANNOTATE_PRINT_COLUMNS_JS tags qualifying .grid-row elements with data-print-2col="true" and sets --print-col-weight CSS variable on each column.
↓
15. Reads BROWSER_PRINT_PDF_HEADER_CONTENT and BROWSER_PRINT_PDF_FOOTER_CONTENT from app config. Builds header/footer templates with HTML-escaped, token-expanded slot content.
↓
16. page.pdf(format="A4", scale=794/1600, margins=18mm/15mm/10mm/10mm, display_header_footer=True, ...)
↓
17. If tab_ids provided (>1 tabs): steps 4–16 repeat per tab at url#TAB-ID; sub-PDFs merged via pypdf.PdfWriter. Falls back to single-URL render if pypdf unavailable.
↓
18. Return bytes → caller. Any exception → return None → fall back to screenshot path.

useSticky Dual-Table Structure (critical)

[data-test-viz-type="table"] (viz root, class "chart-slice superset-v2o9ep")
  ├── table[0]: sticky-header sizer — <thead> with all <th>s, NO <tbody>
  │     └── parentElement: div (overflow:hidden, height:~30px)     ← header-sizer div
  └── table[1]: scrollable body — <tbody> with all rows, NO <thead>
        └── parentElement: div.superset-10a8swc (Emotion scope class)   ← body-scroll div

Both table[0] and table[1] are children of the viz root via their respective parent divs. The Emotion class (superset-10a8swc) is what makes table.table-striped tbody tr:nth-of-type(odd) stripe rule fire. Band-cloned tables lack this scope and need the explicit PRINT_MODE_CSS stripe rule.

D1 — Font-size default bug (Session 8 fix)

DashboardBuilder.tsx was using PRINT_FONT_SIZE_MEDIUM as the fallback when ?print_font_size was absent. This caused getPrintFontSizeCSS('medium') to always inject font-size: 20px !important on table cells, making small and medium tiers indistinguishable. The Superset table plugin's Emotion CSS-in-JS rule sets 12px on .superset-19i2wf4 table.table-condensed — the natural cell size without any override. After fix: small=12px, medium=20px, large=30px (verified via DOM diagnostic after rebuild).

D2 — Table height overflow

After EXPAND_TABLE_CONTAINERS_JS, the table expands to its full scrollHeight. The flex layout chain still allocates the authored pixel height to that cell. Fix: :has(.superset-chart-table) CSS chain releasing height:auto at every ancestor, PLUS the JS walk-up going all the way to .grid-content converting flex→block.

D3 — Tab rendering (antd v6)

antd v6 with animated: { tabPane: false } does not mount inactive tab content even with forceRender:true. In standalone=3 mode the tab nav bar is not rendered at all. Fix: navigate to url#TAB-ID per tab, capture per-tab PDF, merge with pypdf.

D4 — 2-col layout threshold

Old threshold 0.55 was too strict. New threshold: skip only if any column ratio ≥ 0.90. Supports 2 AND 3-column rows. Uses flex-grow with --print-col-weight (proportional weight out of 100).

D5 — Playwright context timeout

context.set_default_timeout(60000) is shared by ALL Playwright calls. For large dashboards it burns through the full 60s before chart readiness is even checked. Fix: pass timeout=effective_wait * 1000 explicitly to page.goto() and locator.wait_for().

D6 — CSS !important cannot override inline React styles

UNHIDE_TAB_PANELS_JS (tab panels) and SET_PRINT_FONT_SIZE_JS (big number font-size) are the correct JS-based fixes.

D7 — position:fixed does NOT produce repeating H/F in Chromium PDF

Only display_header_footer + header_template/footer_template in Playwright's page.pdf() API works. Template font-size defaults to 0px (invisible unless set). Chromium special classes: date, pageNumber, totalPages. Template is rendered at full paper width — independent of page.pdf(scale).

D8 — Table CSS selectors

.dataTable and .table-viz do NOT exist in the live DOM. Use .superset-chart-table td/th. JS targets: .superset-chart-table, [data-test-viz-type="table"], [data-test-viz-type="TableChartTransformed"].

D9 — SCALE_WIDE_TABLES_JS must target scroll container, not inner <table>

The Superset table plugin wraps <table> in a div with style="overflow:hidden; width:Xpx". Applying transform:scale() to the inner <table> does nothing visible — the parent clips the result. Must scale the scroll-container div. Also: sticky <thead> collapses under a CSS transform; fix by setting position:relative on thead and thead th inside the scaled container.

D10 — EXPAND_TABLE_CONTAINERS_JS flex→block and header visibility

After the full JS pipeline (SHOW_ALL_ROWS → EXPAND → MEASURE → BAND → SCALE → ANNOTATE_2COL), confirmed via DOM diagnostic: theadH=29px, headerVisible=True for dash2 (small and 2col) and dash5 (both tabs). The earlier context note about "missing headers" was an intermediate state that was resolved in Sessions 7–8. The header-sizer div retains its natural height (~30px) which correctly contains the 29px thead.

D11 — Pre-commit environment constraints

Mac host runs Python 3.9.6 — too old for zizmor==1.25.2 (requires ≥3.10), so python3 -m pre_commit run fails with CalledProcessError. Docker container has no .git directory (only ./superset:/app/superset is volume-mounted), so pre-commit inside Docker also fails with "not a git repository". Use manual ruff inside Docker + oxlint on host as equivalent validation.
