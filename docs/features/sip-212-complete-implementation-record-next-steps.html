1. What the Feature Does (End-to-End Flow)

Replaces raster-screenshot-stitched PDFs with Playwright's native page.pdf() — a real vector PDF with selectable text. The new path is strictly additive; any failure falls back silently to the existing screenshot path. Gated by feature flag DASHBOARD_REPORTS_BROWSER_PRINT_PDF (default: False).

1. Celery worker → execute.py::_get_pdf()
↓
2. Flag check: DASHBOARD_REPORTS_BROWSER_PRINT_PDF=True AND dashboard report AND single-URL → _get_browser_print_pdf()
↓
3. DashboardPrintScreenshot.__init__ builds URL: base URL + ?standalone=3&print=1 (+ &print_font_size=medium|large if non-small) (+ &print_layout=2col if 2col)
↓
4. Playwright navigates (viewport=1600px wide), authenticates via machine_auth_provider_factory. page.goto() uses explicit timeout=effective_wait*1000 (not context default). Waits 3s headstart. locator(".standalone").wait_for(timeout=effective_wait*1000).
↓
5. Frontend sees ?print=1: DashboardBuilder adds body.print-mode + injects PRINT_MODE_CSS + getPrintFontSizeCSS(tier) + getPrintLayoutCSS(layout) as a single style tag. Row.tsx bypasses IntersectionObserver. Tabs.tsx sets forceRender:true. SliceHeader disables chart-title links.
↓
6. UNHIDE_TAB_PANELS_JS: strips inline style="display:none" from all [role="tabpanel"] elements (CSSMotion renders them hidden even with forceRender).
↓
7. PRINT_ALL_CHART_HOLDERS_READY_JS waits until ALL chart holders (not just viewport-visible) reach terminal state. Uses timeout=effective_wait*1000.
↓
8. EXPAND_TABLE_CONTAINERS_JS: (a) removes inline height+overflow from table scroll containers; (b) walks up the ancestor chain to .grid-content releasing height:auto at every level. SET_PRINT_FONT_SIZE_JS(px) patches inline font-size on .header-line elements for medium (64px) and large (96px) tiers.
↓
9. If print_layout="2col": ANNOTATE_PRINT_COLUMNS_JS tags qualifying .grid-row elements with data-print-2col="true" and sets --print-col-weight CSS variable on each column (proportional flex-grow weight, normalised to 100).
↓
10. Reads BROWSER_PRINT_PDF_HEADER_CONTENT and BROWSER_PRINT_PDF_FOOTER_CONTENT from app config. Builds header/footer templates with HTML-escaped, token-expanded slot content.
↓
11. page.pdf(format="A4", scale=794/1600, margins=18mm/15mm/10mm/10mm, display_header_footer=True, ...)
↓
12. If tab_ids provided (>1 tabs): steps 4–11 repeat per tab at url#TAB-ID; sub-PDFs merged via pypdf.PdfWriter. Falls back to single-URL render if pypdf unavailable.
↓
13. Return bytes → caller. Any exception → return None → fall back to screenshot path.

5. All Technical Discoveries

DOM Structure (confirmed via live inspection)

.grid-content
  .dragdroppable-row           ← flex item per dashboard row
    .with-popover-menu
      .grid-row                ← flex container with sibling columns
        .dragdroppable-column  ← one per chart
          .resizable-container ← re-resizable sets inline style.width here
            .dashboard-component-chart-holder
              .chart-slice
                .dashboard-chart
                  .chart-container
                    .superset-chart-table (if table viz)

D1 — Width source

.resizable-container inline style.width holds the authored px width (e.g. 776px). At 1600px viewport: 4-col≈380px, 6-col≈776px, full≈1568px.

D2 — Table height overflow (root cause confirmed)

After EXPAND_TABLE_CONTAINERS_JS, the table expands to its full scrollHeight (e.g. 10,935px). But the flex layout chain (resizable-container → dragdroppable-column → grid-row) still allocates the authored pixel height (~746px) to that cell. The table overflows its container and physically overlaps the next row in the PDF. Fix: :has(.superset-chart-table) CSS rules releasing height:auto at every ancestor level, PLUS the JS walk-up going all the way to .grid-content/.dashboard-grid.

D3 — Tab rendering (antd v6)

antd v6 with animated: { tabPane: false } completely suppresses inactive tab rendering even with forceRender: true. In standalone=3 mode, the tab NAV BAR is not rendered at all (ant-tabs-tab count = 0). Fix: pass tab_ids (list of TAB-xxx component IDs extracted from dashboard layout JSON) to get_print_pdf; navigate to url#TAB-ID for each tab, capture per-tab PDF, merge with pypdf. Hash URL navigation works: #TAB-4fthLQmdX activates that tab's content.

D4 — 2-col layout threshold

Old threshold 0.55 was too strict — blocked 776+380 and 512+1040 rows. New threshold: skip only if any column has ratio ≥ 0.90 (genuinely full-width chart). Supports 2 AND 3-column rows. Uses flex-grow with --print-col-weight (proportional weight out of 100) instead of fixed width — guarantees columns always fill 100% of row.

D5 — Playwright context timeout vs. explicit timeout (critical)

context.set_default_timeout(60000) is the context-level default for ALL Playwright calls. page.goto(), locator().wait_for(), and page.wait_for_function() all share this budget. For World Bank's Data (18 charts), page.goto(wait_until=domcontentloaded) + 3s headstart + locator(".standalone").wait_for() burned through the full 60s before chart readiness was even checked. Fix: pass timeout=effective_wait * 1000 explicitly to page.goto() and locator.wait_for() — they override the context default independently. page.wait_for_function() already had an explicit timeout.

D6 — .standalone CSS class source

.standalone is set by the Flask template superset/templates/superset/spa.html on <body> when standalone_mode=True is passed. It is a server-rendered class present in the initial HTML, not set by React. Its wait_for() is only slow when the entire page navigation exceeds the context timeout.

D7 — CSS !important cannot override inline React styles

UNHIDE_TAB_PANELS_JS (tab panels) and SET_PRINT_FONT_SIZE_JS (big number font-size) are the correct JS-based fixes. CSS !important loses to inline style= attributes set by React.

D8 — position:fixed does NOT produce repeating H/F in Chromium PDF

Only display_header_footer + header_template/footer_template in Playwright's page.pdf() API works. Playwright template rules: single root element, all styles inline, font-size defaults to 0px (invisible unless set explicitly), Chromium special classes: date, pageNumber, totalPages. Template is rendered at full paper width — independent of page.pdf(scale).

D9 — Table CSS selectors

.dataTable and .table-viz CSS classes do NOT exist in the live DOM. Use .superset-chart-table td/th. JS targets: .superset-chart-table, [data-test-viz-type="table"], [data-test-viz-type="TableChartTransformed"].

D10 — ECharts SVG/canvas labels

ECharts renders axis ticks, legend, pie labels onto SVG/canvas with inline font attributes. CSS cannot reach them; JS cannot patch them post-render without re-rendering. Font-size tiers only affect DOM elements.

D11 — ruff tooling in Docker

Docker venv has ruff and isort but NOT black. Formatting is .venv/bin/ruff format. Linting is .venv/bin/ruff check. Run both before committing.

D12 — Sales Dashboard (dash6) tab structure

TABS-e5Ruro0cjP has children ['TAB-d-E0Zc1cTH', 'TAB-4fthLQmdX']. TAB-d-E0Zc1cTH (first): 3-col rows. TAB-4fthLQmdX (second, inactive): 776px+776px rows → qualify for 2col. Both tabs render correctly in the merged PDF via hash navigation.

D13 — World Bank dashboard (dash2) 2col structure

Row 0: 1172px + 380px table → SKIPPED (hasTable=true). Row 1: 248px + 908px → QUALIFIES. Row 2: 776px + 380px → QUALIFIES. Row 3: 512px + 1040px → QUALIFIES. Row 4: 1040px + 512px → QUALIFIES.

6. Compromises & Known Gaps

C1 — Multi-URL dashboards in report pipeline deferred

_get_browser_print_pdf() returns None if len(urls) != 1 (logs browser_print_pdf_skipped_multi_tab). Note: the test script passes tab_ids directly and handles multi-tab merging correctly at the Python level. The gap is only in the Celery report pipeline — it does not yet extract and pass tab_ids from the dashboard layout JSON.

C2 — JS DOM mutation is fragile works but not ideal

UNHIDE_TAB_PANELS_JS mutates the DOM from outside React. Definitive fix: pass a React context signal to CSSMotion so it never enters the forceRender+display:none branch in print mode.

C3 — No chart-type safety limits not started

No block-list for chart types that may not render headlessly (DeckGL WebGL). No page-count cap.

C4 — ECharts font sizes known limitation

ECharts SVG/canvas labels cannot be controlled by CSS or JS post-render. Font-size tiers only affect DOM elements.
